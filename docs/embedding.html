JavaScript API

Use Hailey inside an existing Node application and keep structured access to results and failures.

Install as a dependency

npm install https://github.com/Malanaa/Hailey/releases/download/v0.1.0/hailey-lang-0.1.0.tgz

The package exports an ECMAScript module. Use a .mjs file or set "type": "module" in your package configuration.

Run a program

import { readFile } from 'node:fs/promises'
import { run } from 'hailey-lang'

const source = await readFile('main.hailey', 'utf8')
const trace = await run(source, {
  maxCalls: 3,
  inputs: { message: 'Please review this ticket' },
  onPrint: text => console.log(text)
})

console.log(trace.status)
console.log(trace.outputs)

run(source, options) parses, checks, constructs a runtime, and executes a flow. It resolves to a trace on success and rejects on failure. Source is the program text, not a filename. No trace file is written by this API.

Keep access to failure traces

import { compile, Runtime, HaileyError } from 'hailey-lang'

const program = compile(source)
const runtime = new Runtime(program, { maxCalls: 2 })

try {
  await runtime.run('main')
} catch (error) {
  if (error instanceof HaileyError) {
    console.error(error.code, error.message)
  } else {
    throw error
  }
}

console.log(runtime.trace)

Create a fresh Runtime for each run or test. A Runtime keeps event state, outputs, the replay cursor, and consumed call count. It is not designed to execute several entry points concurrently or reset itself after a run.

Runtime options

OptionDefaultMeaning
flowmainEntry name used by the run convenience function
maxCalls20Nonnegative integer maximum model attempts
inputsEmpty objectNamed String values used by input(name)
baseDirCurrent working directoryDirectory used to resolve tool file paths
allowReadEmpty arrayDirectory paths allowed for read_text
replayNoneParsed trace object to replay
envprocess.envEnvironment object used for model credential lookup
fetchglobal fetchFetch-compatible function for transport or integration tests
onPrintNoneSynchronous callback receiving formatted print text

When using file tools from a host application, pass baseDir explicitly. This differs from the CLI, which automatically uses the source file's directory. Allowed paths still resolve relative to the host process working directory.

Execute one test

const runtime = new Runtime(compile(source), { maxCalls: 2 })
const trace = await runtime.run('billing', 'test')

The JavaScript API does not apply the CLI's --live gate. The host application chooses whether to execute a program containing live models. Review and validate configuration before running untrusted input.

Replay in a host application

const original = await run(source)
const replayed = await run(source, { replay: original })
console.log(replayed.outputs)

Pass any required inputs again. Replay validates request matching and result types. It does not require a provider credential because no live request is made.

Exported functions

ExportPurpose
compile(source)Parse and check a source string, return an annotated program
run(source, options)Convenience execution returning a successful trace
RuntimeStateful execution object with run(name, kind) and trace
HaileyErrorError class with code and optional source location
parse(source)Parse to an AST without checking
tokenize(source)Return lexical tokens with line and column positions
check(program)Validate and annotate an AST
schemaFor(type, program)Derive JSON Schema for a parsed type
validate(value, schema, path)Validate a value or throw a TYPE error

The high-level compile, run, Runtime, and HaileyError exports are the recommended integration surface. AST internals and checker annotations are early implementation details and may change before 1.0.
