Language reference

The complete v0.1 syntax, data model, and execution rules.

A Hailey program is a UTF-8 text file with the .hailey extension. Top-level declarations define types, models, contexts, tasks, flows, and tests. Declaration order does not matter. Names share a top-level namespace.

Names, comments, and values

Names begin with a letter or underscore and continue with letters, digits, or underscores. Names are case sensitive. Use // or # for line comments. Whitespace separates tokens. Statement terminators are not used.

// A line comment
# Another line comment
flow main {
  let count = 3
  let ready = true
  let missing = null
  let names = ["Avery", "Sam"]
  print names
}

Strings use double quotes and JSON escapes such as \n and \". Triple double quotes create a raw multiline string whose whitespace is preserved. Numbers support decimals, negative signs, and exponent notation. Non-finite numbers are rejected.

Types and data contracts

type Contact {
  name: String
  email: String?
  tags: String[]
}

type Result {
  contact: Contact
  state: "found" | "missing"
}

Every field is required, including nullable fields. Use null for a missing nullable value. Extra object keys are rejected. Recursive types are not supported in this release. A nullable array is written String[]?. There are no arbitrary type unions beyond string enums and the nullable suffix.

Types describe shapeA value can satisfy its type and still be factually wrong. Represent ambiguity in your schema and evaluate model behavior with representative examples.

Models

A model block configures an inference provider. The mock provider is local and deterministic. The compatible provider makes HTTP requests. Model configuration uses constant values.

model fixture {
  provider: "mock"
}

See Models and providers for the full configuration table.

Explicit context

context support_policy {
  text: """
Billing issues go to accounts.
Outages are high urgency.
"""
}

A context contains a nonempty text constant. A task opts into named contexts through context: [support_policy]. Each context is sent as a separate user message in the declared order, after the system message and before the task prompt. There is no automatic retrieval, memory, truncation, or context window fitting.

Typed AI tasks

type Decision {
  team: "accounts" | "support"
  needs_review: Bool
}

model fixture { provider: "mock" }
context policy { text: "Duplicate charges go to accounts." }

task route(message: String) -> Decision {
  model: fixture
  context: [policy]
  system: "Choose a team using the policy."
  prompt: "Message: {{message}}"
  retries: 1
  mock: { team: "accounts", needs_review: false }
}

flow main {
  let decision = route("I was charged twice.")
  print decision.team
}
PropertyRequiredBehavior
modelYesReference to a declared model, without quotes
promptYesNonempty prompt string
systemNoInstruction string, defaults to a request for accurate schema-matching JSON
contextNoArray of declared context names, defaults to empty
retriesNoInteger from 0 to 5, defaults to 0
mockFor mock modelsConstant result that must satisfy the return type

Task arguments are positional. Separate multiple arguments and parameters with commas. Each argument is validated against its parameter type before inference. The result is validated before being returned to the workflow.

Interpolation

Use {{parameter}} or a declared object path such as {{contact.name}} in system and prompt strings. Strings are inserted directly. Other values use JSON serialization. Interpolation happens once, so braces inside an input value are not expanded again. Unknown parameters and invalid object paths fail during checking.

Provider representation

The HTTP adapter asks for an object shaped as { "result": value }, with a JSON Schema derived from the task return type. The wrapper supports both primitive and object results. Workflow code receives the inner value.

Flows and statements

hailey run executes flow main by default. Use --flow name to choose another flow. Statements run sequentially.

flow main {
  let threshold = 3
  assert threshold >= 1
  if threshold == 3 {
    print "Use the normal route"
  } else {
    print "Use the fallback route"
  }
}
  • let name = expression creates an immutable binding
  • print expression writes a value and adds it to trace outputs
  • assert expression requires a Bool and stops the flow when false
  • if condition { ... } else { ... } selects a block, with an optional else branch

Bindings inside a branch are local to that branch. Rebinding and shadowing an existing local name are rejected. There are no loops, mutable assignments, user-defined deterministic functions, return statements, arithmetic operators, or exception handlers in v0.1.

Expressions and precedence

Values include literals, arrays, objects, variable references, field access, task calls, and built-in calls. Equality compares structures, so two arrays with the same values compare equal. Ordering comparisons require numbers. Conditions require Bool values and do not use truthiness.

Built-in functions

FunctionReturnsBehavior
input(name)StringRead a named CLI input. Missing inputs fail with INPUT.
read_text(path)StringRead a regular UTF-8 file up to 1 MiB under an allowed directory. Requires explicit access.

File paths resolve from the source directory. Allowed directories resolve from the shell working directory. Read operations appear in traces with their contents and replay without accessing the file.

Test blocks

test routing_contract {
  let expected = { team: "accounts", needs_review: false }
  let actual = route("I was charged twice.")
  assert actual == expected
}

A test is a named block of the same statements allowed in a flow. Run all tests with hailey test file.hailey. Each test has a fresh runtime and model-call budget. Live model declarations require the explicit --live flag. Test failures do not prevent remaining test blocks from running.

What check does

The checker validates declarations, model settings, type references, mock values, context references, interpolation paths, task arity, literal task arguments, and known object field names. It is not a complete type inference system. Dynamic argument types, conditions, and provider results are also checked during execution.
