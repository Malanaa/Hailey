Traces and replay

See the request, the response, the cost estimate, and the path through your workflow.

Record an execution

Traces are opt-in. Run with --trace and a new filename. No trace is saved automatically if you omit the option.

hailey run main.hailey --trace first.trace.json
hailey inspect first.trace.json

The trace writer opens the target before running and refuses to overwrite an existing file. It requests mode 0600 on operating systems that support Unix file permissions. A runtime failure is recorded in the same trace. Parse errors, check errors, and failures before the trace file is opened do not create a trace.

What a trace contains

FieldMeaning
versionTrace format version, currently 1
sourceHashSHA-256 of the exact source text
entryEntry kind and name, such as flow main
statusrunning, ok, or error
outputsValues produced by print statements, in order
eventsOrdered model attempts and successful file reads
errorTop-level runtime error code and message when the run fails

Model events

Model events include the task name, attempt number, request fingerprint, model alias, provider kind, rendered messages, context names, result schema, validated result when available, raw provider content when available, usage, estimated cost, duration, and failure information. Failed attempts remain in order before a later successful retry.

File events

A successful read_text event records the requested path and full file content. This makes replay independent of subsequent file changes. A denied or failed read appears as a top-level runtime error rather than a successful read event.

  "kind": "model",
  "task": "classify",
  "attempt": 1,
  "model": "local",
  "provider": "mock",

  "estimatedCostUSD": 0

This is an excerpt, not a complete replayable trace.

Replay without another model call

hailey run main.hailey --replay first.trace.json

Replay runs the current workflow logic while taking model and file results from the recording. It performs no new inference calls and does not reread recorded tool files. If your program uses input, pass the same input values again. The trace does not restore CLI inputs automatically.

The runtime checks the trace version, exact source hash, entry point, event order, request fingerprints, result types, remaining event count, and final printed outputs. A changed prompt, source comment, model setting, or relevant input can prevent replay. This strict matching makes a recording a debugging fixture for one program version.

Recorded costs are historicalA replay summary reports the costs stored in the original recording. It makes no new inference request. Do not treat a replayed cost as a new charge.

Debug a failing workflow

  1. Run with a new trace filename
  2. Inspect the top-level error code
  3. Find the last model or file event
  4. Compare the rendered messages and schema with your intended task
  5. Use replay to reproduce a recorded provider or validation failure where applicable
  6. After editing the program, make a fresh recording

A provider error event includes a stable error category and a sanitized message. Upstream HTTP error bodies are not copied into the trace. Successful provider content can still include sensitive data.

Data and trust

A trace can contain the entire requestPrompts, context text, model output, and file contents may include personal or business data. Review a trace before sharing it and keep recordings out of public repositories.

Environment credential values are not added to metadata. This is not general secret redaction. If you put a secret in a prompt or source file, it can appear in a trace. Trace JSON is unsigned and editable. Source and request hashes detect accidental mismatches, not malicious modification.

Replay boundaries

Replay does not make fresh model inference deterministic. It does not resume halfway through a workflow, automatically migrate between language versions, or guarantee reproduction of external filesystem failures. There is no interactive trace viewer in v0.1. Use hailey inspect, a JSON editor, or your own reporting tools.
