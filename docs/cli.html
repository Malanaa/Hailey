Docs / CLI reference

CLI reference

Every command, flag, execution limit, and failure category in v0.1.

Commands

CommandBehavior
hailey init [directory]Create a directory if needed and write a starter main.hailey with exclusive creation
hailey check file.haileyParse and check without model calls or tool file reads
hailey run file.haileyRun flow main unless another flow is selected
hailey test file.haileyRun every test block in declaration order
hailey inspect file.trace.jsonRead and print a version 1 trace as formatted JSON
hailey versionPrint the version, also available as --version or -v
hailey helpPrint usage, also available as --help or -h

Run options

OptionDefaultBehavior
--flow namemainSelect a declared flow
--input name=valueNonePass a String to input(name), repeatable with distinct names
--max-calls N20Maximum total model attempts, including retries
--trace pathOffCreate a new JSON recording, refuses an existing path
--replay pathOffUse a matching saved recording
--allow-read directoryNo file accessAllow read_text under a directory, repeatable
hailey run app.hailey --flow review --input "message=Please review my ticket" --max-calls 3 --trace review.trace.json

Inputs remain strings. An input value can contain an equals sign after its first separator. Duplicate input names, duplicate single-use options, unknown options, and missing option values fail with a CLI error. Flags follow the source filename.

Test options

Tests accept --input, --max-calls, and --allow-read with the same meaning. They also accept --live to enable files that declare compatible providers. Each test starts with a fresh runtime and call budget.

hailey test examples/triage.hailey
hailey test paid-evaluation.hailey --live --max-calls 2

A test file with no test blocks returns an error rather than a misleading success. Test runs do not currently support trace or replay CLI flags. Use the JavaScript Runtime API to inspect an individual test trace.

Execution bounds

--max-calls 0 prevents model attempts while allowing pure workflow statements. A retry consumes another attempt. The limit is checked before inference begins.

timeout_ms is a per-request model setting, not a whole-run deadline. max_output_tokens is a requested provider output limit. Hailey does not have a total token budget, automatic context trimming, or a hard dollar limit in v0.1.

Output and exit status

Program print statements go to standard output. Run summaries and errors go to standard error. Check and test commands print their status to standard output, with failures also reported on standard error.

Exit statusMeaning
0Command completed successfully
1Parse, check, input, provider, runtime, assertion, trace, or filesystem failure

File access example

hailey run examples/files.hailey --allow-read examples --trace files.trace.json
hailey run examples/files.hailey --replay files.trace.json

Allowed directories are interpreted from the current working directory. Tool file paths are interpreted from the program directory. Symlink targets must remain inside an allowed canonical directory. These checks do not replace an operating system sandbox.
