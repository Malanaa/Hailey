Models and providers

Move from deterministic fixtures to real inference with explicit configuration and honest cost reporting.

Start with the mock provider

The mock provider returns a task's declared fixture exactly. It does not inspect the prompt or synthesize a result. This is useful for offline development, deterministic workflow tests, and package verification.

model local { provider: "mock" }

task greet(name: String) -> String {
  model: local
  prompt: "Greet {{name}}"
  mock: "Hello, Avery"
}

flow main { print greet("Avery") }

Connect a compatible endpoint

The compatible adapter implements the Chat Completions request and response format. Configure the full POST endpoint, not just a base URL. Compatibility varies across providers, model families, and local servers.

// Choose a model available through your provider.
// This example makes a paid network request when configured.
type Ticket {
  category: "billing" | "bug" | "question"
  summary: String
  needs_review: Bool
}

model remote {
  provider: "compatible"
  endpoint: "https://api.openai.com/v1/chat/completions"
  api_key: "OPENAI_API_KEY"
  name: "gpt-4.1-mini"
  max_output_tokens: 512
  timeout_ms: 30000
  format: "json_schema"
}

task classify(message: String) -> Ticket {
  model: remote
  system: "Classify support requests. Set needs_review when the message is ambiguous."
  prompt: "{{message}}"
  retries: 1
}

flow main {
  let ticket = classify(input("message"))
  print ticket
}

Save this as live.hailey, then set your credential in the shell and run the flow.

export OPENAI_API_KEY="your-api-key"
hailey run live.hailey --input "message=I was charged twice" --max-calls 2 --trace live.trace.json

For PowerShell, use $env:OPENAI_API_KEY = "your-api-key". The api_key property contains an environment variable name, never the credential itself. Hailey does not automatically read a .env file.

Choose your own modelThe example names a model for illustration. Verify availability, supported request fields, and pricing with your provider. No paid provider call was used to validate this release.

Model settings

SettingDefaultMeaning
providermockmock or compatible
nameNoneRequired provider model identifier for compatible models
endpointNoneRequired full HTTP POST endpoint for compatible models
api_keyNoneOptional environment variable containing the Bearer token
max_output_tokens512Positive integer sent to the provider as the output limit
timeout_ms30000Per-attempt HTTP timeout in milliseconds
formatjson_schemajson_schema for strict schema requests, or json_object for JSON mode
token_parametermax_completion_tokensSet max_tokens for endpoints that require that field
input_priceUnknownUSD per million input tokens, must be paired with output_price
output_priceUnknownUSD per million output tokens, must be paired with input_price

Use HTTPS for remote endpoints. HTTP is permitted only for localhost, 127.0.0.1, or [::1]. URLs cannot contain credentials, query parameters, or fragments. The adapter rejects redirects rather than forwarding credentials elsewhere.

Local server configuration

model local_server {
  provider: "compatible"
  endpoint: "http://127.0.0.1:1234/v1/chat/completions"
  name: "your-loaded-model"
  format: "json_object"
  token_parameter: "max_tokens"
  max_output_tokens: 512
}

This is a configuration pattern, not a server installer. Start a server that supports this route and response format, then use its port and loaded model name. JSON mode still receives the schema as part of the system message, and Hailey validates the returned value locally.

Cost reporting

Hailey reads prompt_tokens and completion_tokens from provider usage metadata. Set both price fields when you want an estimate. These illustrative prices are not a quote for any model.

// Illustrative only. Replace with your provider prices.
model priced {
  provider: "compatible"
  endpoint: "https://your-provider.example/v1/chat/completions"
  name: "your-model"
  input_price: 2
  output_price: 8
}

The estimate is (input tokens × input price + output tokens × output price) / 1,000,000. It does not include separate cache rates, tools, images, taxes, discounts, or other provider billing details. A billed response that fails schema validation still contributes its reported usage. Missing usage or missing prices produce null cost, and the CLI counts those attempts as unpriced.

Visibility is not a dollar capThe runtime limits attempts, while the provider controls token generation and billing. An HTTP timeout can happen after a provider has started billable work. Configure provider-side spending controls when needed.

Retries and failures

A task can set retries from 0 to 5. The default is zero. The runtime retries invalid JSON, type-invalid outputs, network failures, timeout errors, and HTTP 408, 429, 500, 502, 503, and 504. Delays start at 250 ms and double to a maximum of 4 seconds.

Authentication failures, explicit model refusals, and truncated outputs fail immediately. Every attempt consumes the same run-level call budget. With --max-calls 2, no third model attempt can begin, even if the task asks for more retries.

Protocol references

The request format follows the official Chat Completions reference. Other compatible providers may implement only part of that protocol. Consult your chosen service before switching formats or token-limit fields.
